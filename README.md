# I Told You So

독립적으로 발견한 음악을 간직하는 **개인 음악 발견 기록장**입니다.
언제 발견했는지, 어디서 들었는지, 무엇이 좋았는지, 이후 어떻게 변했는지를 남깁니다.
인기는 발견의 가치를 결정하지 않습니다. 먼저 발견하고, 인정은 나중에 올 수도 있어요.

- 아티스트와 곡 제목만으로 저장할 수 있습니다. 수치, 이유, 예측, 링크 모두 선택입니다.
- 1인용, 수동 입력. 음악 추천이나 Spotify·YouTube·Last.fm API를 쓰지 않습니다.
- 서버·DB 없이 로컬로 동작합니다. 데이터는 브라우저(localStorage)에 저장되고 JSON으로 백업/복원합니다.
- 한국어/English, 라이트/다크, 모바일 하단 탭. 종이·잉크와 도장 디자인을 유지합니다.
- 이 기록은 수정할 수 있는 개인 기록입니다. 독립적으로 검증된 증거나 암호학적으로 인증된 발견 시점이 아닙니다.

## 쓰는 흐름

| 화면 | 하는 일 |
|---|---|
| **발견 목록** `#/` | 모든 픽을 장부처럼 봅니다. 상태(추적 중·적중·하차) 탭, 검색(곡·아티스트·태그), 정렬(최근 픽·성장률·오래 안 본 순). 체크인할 곡이 있으면 맨 위에 알려줍니다. |
| **새 픽** `#/new` | 아티스트·곡·발견 일시만으로 저장. 접어둔 선택 항목에서 링크, 발견 맥락, 메모, 관찰 수치와 관찰 일시, 출처, 예측, 태그를 추가합니다. 어디서든 `n` 키, 저장은 `⌘/Ctrl+Enter`. |
| **상세** `#/p/:id` | 발견 당시 수치와 나중의 첫 관찰 기준을 구분한 수치표, 개인 메모, 성장 배수, 추이 그래프(범위가 크면 로그 눈금), 이유, 체크인 기록 추가/삭제, 공유 카드, 적중 표시·하차·삭제(되돌리기 가능). |
| **체크인** `#/checkin` | 설정한 주기(새 사용자는 기본 30일, 기존 설정은 유지) 넘게 그대로인 곡을 한 화면에서 몰아서 업데이트. 칸마다 지난 값 대비 변화율이 바로 보입니다. |
| **전적** `#/record` | 낮은 발견 당시 수치에서 성장한 음악을 지표·출처별로 보여줍니다. 기존 통계와 12개월 막대, 접어서 볼 수 있는 업적 37개(달성일과 진행도)를 유지합니다. |
| **설정** `#/settings` | 적중 기준 배수, 월 픽 한도, 체크인 주기, 언어·테마, 백업(JSON/CSV). |

### 수치 입력

유튜브·스트리밍 앱에 보이는 숫자를 그대로 옮기면 됩니다. `12,345`, `1.2M`, `3.4K`, `12만`, `1억 2천만`, `4.5만회` 모두 읽고, 어떻게 읽었는지 입력칸 아래에 보여줍니다.

### 적중 판정

- 픽마다 **기준 지표**가 하나 있습니다(입력한 지표 중 선택).
- 체크인한 기준 지표가 **첫 관찰값의 ×2**(설정에서 1.5–10배)에 닿으면 자동 성장 달성으로 표시됩니다. 100 → 200 조회수도 성장 달성이지만 유명해졌다는 의미는 아닙니다.
- **예측**을 적어두었다면 그 수치를 넘는 순간에도 적중입니다.
- 수치로 드러나지 않는 성공(수상, 차트 진입 등)은 상세 화면에서 직접 적중으로 표시할 수 있습니다.
- 기준 배수를 바꾸거나 체크인 기록을 지우면 자동 적중은 다시 판정됩니다. 직접 표시한 적중은 그대로 둡니다.

### 날짜·기준값·출처

- **발견일**(`claimedAt`)은 사용자가 발견했다고 기록한 시점입니다. **생성일**(`createdAt`)은 이 웹사이트에 기록을 만든 시점이며 수정해도 보존됩니다.
- **첫 관찰일**과 **최근 관찰일**은 지표마다 다릅니다. 성장률은 해당 지표의 첫 관찰값을 기준으로 합니다. 양수인 기준값과 서로 다른 시점의 관찰 두 번이 있어야 배수를 계산합니다. 0과 누락은 서로 다릅니다.
- 발견 당시 수치는 관찰 시점이 발견 시점과 일치할 때만 표시합니다. 1월 10일에 발견하고 4월 10일에 처음 기록한 월간 청취자 15,000명은 1월의 수치로 표시하지 않습니다.
- 수치 없이 기록해도 목록·상세·JSON·CSV에 남습니다. 첫 관찰은 나중에 상세 화면이나 일괄 체크인에서 추가할 수 있습니다. 그때까지 성장률은 미정입니다.
- 관찰 수치에는 선택적으로 플랫폼과 특정 영상/발매곡/아티스트 페이지를 적습니다. 영상 조회수와 곡 스트리밍은 고유 청취자 수가 아니고, 월간 청취자는 아티스트 단위입니다.
- 지정한 출처는 그 지표의 기록에 고정됩니다. 다른 영상이나 발매곡은 별도 기록을 만드세요. 기존 데이터의 출처는 자동 추정하지 않습니다. 과거 출처를 아는 사용자가 직접 적을 수 있습니다.
- 발견 초기순 정렬은 지표와 출처를 선택하고 발견 당시의 알려진 수치만 비교합니다. 알 수 없는 값은 마지막에 나옵니다. 전적의 주목할 발견은 발견 당시 1만 미만에서 두 배 이상 성장한 음악을 지표·출처별, 최신 발견순으로 보여줍니다. 서로 다른 지표를 섞은 종합 점수는 없습니다.

### 성장과 성공

저장된 상태(`watching`, `hit`, `dropped`)와 기존 규칙은 유지합니다. 표시에서는 **성장 기준 달성**, **예측 달성**, **직접 확인한 의미 있는 성공**을 구분합니다. 자동 달성 확인일은 조건을 처음 만족한 실제 관찰일입니다. 예측은 발견 이후 첫 관찰에서 달성할 수도 있습니다. 직접 확인한 성공은 설정을 바꿔도 유지됩니다.

새 사용자는 월 발견 한도 **무제한(0)**과 체크인 안내 **30일**을 기본으로 사용합니다. 기존 사용자의 한도와 주기는 바꾸지 않습니다. 안내는 마감이나 실패 판정이 아닙니다.

## 배포 (GitHub Actions → GitHub Pages)

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다(한 번만).
2. `main`에 push하면 `.github/workflows/deploy.yml`이 `npm ci → lint → typecheck → test → build`를 돌리고 `dist/`를 Pages에 배포합니다.
3. 주소: `https://<사용자명>.github.io/itoldyouso/`

- 라우팅은 해시(`#/…`) 방식이고 에셋 경로는 상대 경로(`base: './'`)라서 저장소 이름이 바뀌거나 커스텀 도메인을 붙여도 설정을 고칠 필요가 없습니다. 새로고침·직접 링크도 404가 나지 않습니다.
- PR에는 검사와 빌드만 돌고 배포는 하지 않습니다.
- 설정 화면 맨 아래에 빌드 커밋과 시각이 표시되어 배포가 반영됐는지 확인할 수 있습니다.

## 데이터와 백업

- 모든 기록은 이 브라우저의 localStorage(`itys-vault`)에만 있습니다. 외부로 전송되는 데이터는 없습니다(웹폰트·YouTube 썸네일 이미지 요청만 있음). 브라우저 데이터를 지우면 사라지므로 **설정 → 백업 → JSON 내보내기**로 가끔 받아두세요. 마지막 내보내기 시점이 표시됩니다.
- JSON 가져오기는 **합치기**(같은 픽은 더 최근에 수정된 쪽 유지)와 **전부 교체** 중에서 고릅니다. 다른 기기로 옮길 때도 이 방법을 씁니다.
- CSV 내보내기는 엑셀/스프레드시트용입니다(한글 깨짐 방지 BOM 포함).
- 공유 카드는 서버 없이 브라우저 캔버스에서 그립니다(스토리 9:16, 정사각 1:1).

### 문서 v3 호환성

Zustand 저장소 이름은 `itys-vault`를 그대로 사용하고 저장소/JSON 버전을 **3**으로 올렸습니다. v2 저장소는 로드 시 명시적으로 정규화하여 이전하고, v2 JSON 백업도 가져올 수 있습니다. 미래의 알 수 없는 JSON 버전은 거부합니다.

- 기존 관찰값·날짜·메모·태그·링크·예측·상태·설정과 삭제 기록을 보존합니다. 빈 초기 관찰과 관찰이 없는 발견도 유효합니다. 빠진 숫자, 출처, 생성일, 달성일을 만들어내지 않습니다.
- 새 선택 필드는 `discoveryContext`, `metricSources`입니다. 발견·생성·관찰 날짜는 서로 독립적입니다. JSON은 전체 기록을 담고, CSV는 발견 당시/첫 관찰/최근 값과 관찰 날짜, 출처, 생성일, 맥락, 달성 이유를 포함합니다. CSV는 전체 복원용 형식이 아닙니다.
- 합치기는 기존의 최신 수정 우선/삭제 기록 규칙을 유지합니다. 교체 가져오기는 의도적으로 수정 시각을 현재로 갱신하여 이후 합치기에서 교체한 사본이 유지되게 합니다. 발견일·생성일·관찰일은 바꾸지 않습니다.
- v3 백업은 구버전 앱에 역으로 가져오지 마세요. 구버전은 수치 없는 발견과 새 선택 필드를 보존하지 못할 수 있습니다.
- 자동 동기화나 외부 검증은 없습니다. 브라우저/기기마다 독립된 저장소이며 사이트 데이터 삭제 시 사라집니다. JSON 백업을 별도 위치에 보관하세요.

## v2에서 바뀐 점

- Spotify 로그인·검색, YouTube Data API, Last.fm API 호출을 모두 없애고 수동 입력으로 바꿨습니다. API 키가 필요 없습니다.
- 다중 사용자 기능(피드, 공감, 선구자, 프로필)을 걷어내고 1인용 흐름(목록 → 픽 → 체크인 → 적중)으로 화면을 다시 짰습니다. 새로 생긴 체크인 화면에서 여러 곡을 한 번에 업데이트합니다.
- 추적 지표를 조회수·스트리밍·월간 청취자로 정리하고, 곡마다 기준 지표와 예측을 둘 수 있게 했습니다. "바이브 지수" 대신 배수/퍼센트로 표시합니다.
- 업적을 35개에서 37개로 다시 설계했습니다. 판정 로직이 없던 배지, 서로 조건이 겹치던 배지, 설명과 실제 조건이 다르던 배지를 정리했고, 모든 업적에 달성일과 진행도가 나옵니다.
- Supabase 연결(로그인, DB 테이블, 마이그레이션, 환경 변수)을 모두 없애고 로컬 전용으로 바꿨습니다. 빌드에 시크릿이 필요 없습니다.
- GitHub Pages에서 깨지던 라우팅(basename 누락)을 해시 라우팅 + 상대 경로로 바꿨습니다. 워크플로에 검사 단계와 PR 빌드를 추가했습니다.
- 디자인을 종이·잉크 톤의 장부 스타일로 바꿨습니다(IBM Plex Sans KR/Mono, 도장 빨강 한 가지 강조색, 한국 증시식 상승=빨강/하락=파랑). 다크 모드를 지원합니다.
- recharts·framer-motion·html2canvas·colorthief·@supabase/supabase-js 의존성을 없애 번들을 줄였습니다.
